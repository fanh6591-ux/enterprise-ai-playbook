# 餐饮库存与菜单推荐｜场景拆解

## 公开方案背景

Isaac 的[巴奴公开项目说明](https://isaac2024.online/work/details/banu/)保留了一个历史阶段的方案设计：结合 POS、ERP 里的库存、消耗、销量、损耗、调货和原料映射，再考虑人数、时段、客单价与加菜习惯，连接到菜单推荐和晚间促销。

## 先定义经营动作

同一次菜单推荐，需要回答三个具体问题：哪些菜符合这一桌的需求？当天哪些食材需要优先周转？这次优惠带来了多少真正新增的消费？

| 连接点 | 需要明确的口径 |
| --- | --- |
| 菜品与原料 | 一个菜品对应哪些原料、用量怎样计算 |
| 库存状态 | 可用库存、库存时间、当日消耗和缺货条件 |
| 顾客与用餐 | 人数、时段、已有点单和加菜需求 |
| 推荐动作 | 候选菜品、排序理由、展示时机与确认人 |
| 经营结果 | 新增消费、折扣成本、食材损耗和库存周转 |

## 为后续试点设计验证

以下为方法建议，需由业务方确定可行的试点方式：

- 记录现有推荐和促销方法，建立相同时段与经营条件下的基线。
- 在候选工作流中保留推荐依据，便于门店人员检查库存和业务规则。
- 用可比较的试点安排区分新增加菜与原本就会发生的消费。
- 同时记录收入、折扣、毛利口径与食材损耗，再由业务方判断价值。
- 使用[需求卡](../templates/project-brief.md)和[验收计划](../templates/acceptance-plan.md)对齐范围、负责人和采用条件。
